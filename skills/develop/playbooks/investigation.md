### Investigation

**You own the answer. Plan, route, write.**

Investigation requests are read-only. They produce a cited explanation or recommendation, never a code edit.

1. Trace the code the question is about. For motivation or history questions, also run the **why** skill. For deep subsystem walkthroughs, use the **how** skill.
2. Produce a clear answer (Overview, Key Concepts, How It Works, Where Things Live, Gotchas), or a recommendation with a tradeoffs table when choosing between alternatives.
3. Apply the **unslop** skill to the reply.

No PR, no code edits, and no **architect** unless the investigation precedes a planned change. If it does, hand back the findings and re-route to Bug fix or Feature once confirmed.

**Reply:** the cited investigation output. For "are we sure?" questions, give your direct judgment with evidence and push back if the premise is wrong.
